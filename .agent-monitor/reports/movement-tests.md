# T-MOVE 입력 → 물리 이동 검증

검증 대상은 `tests/movement.test.ts`이며 `src/game/engine.ts`는 수정하지 않았다. 기존 `tests/engine.test.ts`의 “대시는 한 입력에서 한 번만 시작” 검사는 중복하지 않았다.

## 검증 범위

- 실제 월드 크기 `halfWidth=1000`, `halfHeight=680`에서 플레이어 반지름 15를 반영한 네 방향 경계 제한
- 축 이동과 대각선 이동의 동일 거리 정규화
- 생성된 월드의 solid 벽과 비-solid 장식 문에 대한 충돌 차이
- 한 물리 호출당 60단위가 되는 고속 대시에서 10단위 분할이 반경 5 소품의 터널링을 막는지 확인
- 모서리에서 solid 소품 반발 후 좌표가 월드 안에 있고 소품과 겹치지 않는지 확인
- 월드 모서리에서 서로 겹친 두 solid 소품의 제약도 동시에 해소하는지 확인
- `NaN`, `Infinity`, `-Infinity`가 섞인 이동축 및 대시 입력 뒤 `x`, `y`, `facing` 유효성

## 실행 결과

실행 명령: `npx tsx --test tests/movement.test.ts`

- 수정 전 1차: 6개 중 5개 통과, 1개 실패
- 수정 전 2차: 6개 중 5개 통과, 같은 1개 실패
- 물리 제약 해소 수정 및 겹친 두 소품 사례 추가 후: 7개 모두 통과
- 최종적으로 경계, 대각선 정규화, solid/장식 구분, 대시 터널링 방지, 단일/복수 소품과 월드 경계의 동시 제약, 비유한 입력 정제가 모두 통과했다.

## 재현 및 수정 확인

실패 테스트: `월드 모서리 소품의 반발 뒤에도 플레이어는 경계 안에 남는다 (unit fixture)`

플레이어를 우하단 유효 최대 좌표 `(985, 665)`에 두고, 그 안쪽 1단위 지점 `(984, 664)`에 반경 20 solid 소품을 둔 뒤 입력 없이 0.01초 진행하면 플레이어 좌표가 `(1008.7487373415291, 688.7487373415291)`이 된다. 허용 최대값 `(985, 665)`를 두 축 모두 `23.7487373415291`만큼 벗어난다.

원인은 `moveBody`가 각 이동 조각에서 먼저 월드 경계를 clamp한 다음 solid 소품 반발 위치를 대입하고, 그 결과에 경계 clamp를 다시 적용하지 않는 순서다. 모서리 안쪽 소품에서 바깥쪽을 향하는 반발 벡터가 선택되면 정상 입력 여부와 관계없이 좌표가 경계 밖으로 남는다.

수정 시 소품 반발 뒤 경계 불변식과 소품 비겹침을 함께 만족하는지 확인해야 한다. 단순 후처리 clamp만 하면 플레이어가 경계 안에서는 소품과 겹친 채 남을 수 있으므로, 모서리에서 가능한 안쪽 분리 방향 또는 경계 제약을 포함한 충돌 해소가 필요하다.

수정 반영 뒤 동일 fixture는 경계와 소품 비겹침 조건을 모두 통과했다. 반경 20인 두 solid 소품의 중심을 `(975, 655)`, `(955, 655)`에 두어 소품끼리 겹치고 플레이어도 양쪽 충돌 반경 안에서 시작하는 추가 fixture 역시, 최종 좌표가 월드 안에 있고 두 소품 모두와 겹치지 않음을 확인했다.
