# V01 실제 플레이 불일치 분석

작성: combat / reviewer / 전투·입력 재현, 2026-09-19. 대상 P0 동결 엔진. 브라우저는 직접 조작하지 않았고 메인 캡처·기록, 코드 읽기와 공개 API 시뮬레이션으로 분석했다.

## 결론

145초 패배와 기존 seed 42의 600초 승리는 **서로 다른 입력 정책·시드에서 나온 결과**다. 현 근거는 장애물을 고려하지 않은 시험 봇의 이동 선택 실패를 지지하며, 엔진의 피해 계산 또는 입력 처리 결함으로 판단할 근거는 발견하지 못했다. 게임 난이도·충돌·회복·무기 수치는 수정하지 않았다. P0 엔진 동결을 유지한다.

기존 단일 시드의 headless 승리는 가능한 승리 경로의 확인이며, 일반적인 봇 생존율 또는 실제 키보드 플레이 검증을 대신하지 않는다.

## 직접 확인한 증거

- `evidence/p0-normal-combat.png`를 이미지로 열어 확인했다. 120초 화면의 플레이어는 성벽 위쪽과 나무 사이에 있고, 아래쪽에는 회복·XP 아이템이 남아 있다. 고블린의 돌진 예고가 접근한다.
- `p0-normal-result.json`: 145.12초 패배, Lv7, 누적 피해 223.27, 최대 동시 적 11, 처리되지 않은 오류 0, RAF 루프 1개다.
- 90.35초에서 120.43초 사이 HP 110.05→27.06, Lv7 유지, 픽업 12→48, 적 8→5다. 성장 수집이 중단되고 피격이 누적된 상태다. 적 수 급증으로 해석할 근거는 없다.
- `p0-normal-progress.json`의 키 상태는 A+S로, 플레이어 이동 입력이 실제 전달되고 있었다.
- 기존 `scripts/play-session.mjs`는 적 88px 내 거리 회피합을 최우선으로 정하고, 그 밖에는 가장 가까운 회복/XP로 직진한다. `props`와 `zones`를 이동 의사결정에 사용하지 않는다. 따라서 회피합이나 수집 목표가 벽 반대편을 향하면 같은 방향으로 계속 밀 수 있다.
- 기존 headless hunter는 매 프레임 연속 방향으로 이동했고, 실브라우저는 약 100ms마다 8방향으로 입력하며, 위험거리도 75→88px로 달랐다. 시드도 달랐다.

## 별도 입력 재현

게임 상태·수치 변경 없이 `createGame` / `step` / `selectUpgrade` 공개 경로로 6개 시드 × 2정책을 확인했다. 원본 입력 비교 코드와 상세 결과는 `/tmp/lrg-analysis.ts`, `/tmp/lrg-analysis.jsonl`이다. 이 임시 파일은 제출물로 간주하지 않는다.

| 시드 | 기존 연속방향 / 60Hz | 이전 브라우저 근사 / 100ms·8방향 |
|---|---|---|
| 42 | 600초 승리 | 183초 패배 |
| 1 | 390초 패배 | 170초 패배 |
| 7 | 316초 패배 | 600초 승리 |
| 123 | 147초 패배 | 600초 승리 |
| 999 | 600초 승리 | 586초 패배 |
| 2026 | 513초 패배 | 600초 승리 |

결과는 입력의 작은 차이와 시드가 경로를 바꾸며, 장애물 회피가 없는 전략 자체가 불안정함을 보여 준다. seed 42의 8방향 실패에서는 누적 42초 동안 입력 중 실제 이동이 0.4px/frame 미만이고 고체 소품 접촉 범위였으며, 해당 정체 프레임의 피해가 총 225 중 109였다. 180초 위치 `(441,-549)`는 성벽과 나무가 가까운 곳이다. 연속방향에서도 동일 지형의 정체와 실패를 관측했으므로 키보드 또는 프레임 속도만의 결함으로 볼 수 없다.

## 메인 조치와 재검증

메인이 `scripts/steering.mjs`에 고체 소품, 공격 예고, 경계와 후보 8방향의 안전도를 반영했다. 코드를 읽어 게임 상태를 변경하지 않고 입력만 반환하는 것을 확인했다. 접근 가능한 중앙 뜰의 수집 목표와 경로를 선택하는 시험 전략 변경이다. 게임 코드의 난이도를 낮추는 변경은 없다.

메인 보고에 따르면 수정 전략을 100ms·8방향, 시드 42/12345/76387로 실행하여 각각 600초 승리와 두 시너지를 확인했다. 이는 메인 보고 기반 시뮬레이션 결과이며 실제 브라우저 재검증은 메인이 별도로 수행한다.

다음 실브라우저 기록에는 시드, 플레이어 좌표, 최종 플레이어 상태를 추가한다. 정확한 입력 이력 없이 최초 랜덤 시드 판 전체를 재생했다고 주장하지 않는다. 최초 실패 결과와 캡처를 보존하고, 수정한 시험 입력 정책의 새 결과를 별도 이름으로 남긴다.
